# Idea-round quality bar

Run this top to bottom before submitting. An unchecked line blocks the submission, unless a dated line under `## Decisions` in `BULLSEYE.md` says why it does not apply to this round.

## Format

- [ ] Every fact this round depends on is in `## Contract` with a source: medium, counts, field limits, file caps, naming, fonts, links, anonymity, edits after submitting, shortlist dates, jury
- [ ] Field names and limits copied verbatim from the portal or the instructions
- [ ] Every R line for this round maps to an artifact in the Round plan of `idea/SPINE.md`
- [ ] Rhythm chosen: v1 early when edits are allowed, or one submission at least 24 hours early when submitting locks the entry

## The six

- [ ] Numbers in the problem statement, each with a source
- [ ] An architecture diagram, with planned parts dashed and labelled
- [ ] Named data sources
- [ ] Declared metrics: the target, how and on what it is measured, against which baseline
- [ ] A real-world deployment path with market size
- [ ] An honest scope for the build window

## Story

- [ ] All 14 parts drafted, or marked "not used" with the reason
- [ ] The 14 headlines alone argue the case
- [ ] The problem opens on one dated incident with three numbers
- [ ] The "solved elsewhere" row carries years
- [ ] The product mock features the uncertain case handed to a human
- [ ] Every rubric criterion has evidence and a place where it shows
- [ ] The close has a small, specific ask

## Proof

- [ ] Organiser data: leakage audited with evidence printed, out-of-fold validation, rare-event metrics, an interval on the headline, the brief's own baseline in the same pipeline, latency with its scope, any proxy labelled inside its callout
- [ ] No data: a thin vertical prototype, screenshots, a 90-second recording, the repo link when the form takes links
- [ ] PROVEN vs OPEN RISKS written
- [ ] Proof scripts committed with relative paths; results in JSON; a Methods line for each measured number

## Honesty

- [ ] Every number labelled on the artifact: SOURCED, MEASURED, SIMULATED, PROJECTED, TARGET or ILLUSTRATIVE
- [ ] A status chip on every product slide, at today's honest level
- [ ] Mock-ups labelled inside the frame; no mock-up in a slot meant for a real photo or screenshot
- [ ] The unflattering comparison disclosed beside the flattering one
- [ ] No unverified claim: mandates, partners, pilots, adoption, endorsements
- [ ] Autonomy claims match what a human approves
- [ ] The closest prior art named; competitors rated fairly
- [ ] Hard-critic review and cross-model check done; the Claims changed table is current
- [ ] No em dashes in judge-facing text

## Formats and files

- [ ] Brief, deck and form carry the same numbers and headlines (drift check against the Numbers table)
- [ ] Organiser template: every section in order, its wording as kickers, prompt text blanked, branding untouched
- [ ] The official cut is its own file: slide count, size cap, fonts embedded, naming rule
- [ ] Every page of every exported file looked at as rendered
- [ ] Generators and their inputs committed next to their outputs
- [ ] Disclosure of existing work on the artifact when anything pre-existed

## Form

- [ ] `form-check.mjs` exits 0 with this portal's `--forbid` characters
- [ ] `form-check.mjs --numbers idea/SPINE.md` reports nothing missing
- [ ] Binding limits filled 91 to 97%; generous limits hold what a judge will read, no more
- [ ] Plain text, form-safe characters, dropdown options copied exactly
- [ ] Every link opens in a logged-out browser

## Government and funding calls

- [ ] Eligibility confirmed by the human; the category is final
- [ ] Five decisions recorded: idea, theme, category, host institute, applicant
- [ ] The host institute consulted before submitting
- [ ] No identity in the text, the files or their metadata; no forbidden references; nothing copied
- [ ] The applicant intends to build it

## Submission

- [ ] The human who submits has the login, the files, the paste order and the dropdown table
- [ ] Stored fields re-read after submitting; a screenshot of the submitted view and the confirmation saved in the private `brief/` folder
- [ ] `SUBMITTED <date time TZ> · under review` in `BULLSEYE.md`, the next gates dated, the tracker row updated
